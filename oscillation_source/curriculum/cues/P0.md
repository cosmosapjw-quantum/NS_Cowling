# P0 · 내 소스를 그대로 독립 실행하기

**선행:** A21　 **독립 작업:** 0.5–1시간 (계획치)

## 옮긴 것은 실행파일인가, 자신이 작성한 계산인가?

새 폴더에서 결과가 나왔다. 이전 binary를 사용한 것인지 소스로부터 만든 것인지 어떻게 구별할지, 복사 전에 필요한 파일을 적자.

먼저 한두 문장으로 답한 뒤 아래 설명을 읽자. 첫 예측이 틀렸거나 아직 모르겠다고 적는 것은 감점하지 않는다.

## 필요한 관계와 읽을 위치

이 과제는 물리 방정식의 추가가 아니다. 동일한 소스와 공용 의존성을 보존하고, 다른 위치에서 실제로 빌드·실행할 수 있는지 확인한다.

`notes/chapters/ch11.md`, `tools/export_learner.py`, `tools/verify_export.py`, `tools/make_calculation.py`

## 계산으로 옮기기

P1–P4의 자동 검사는 직접 구현한 learner의 독립 export 경로다. 제공 계산만 사용하는 독자는 별도 계산 폴더에서 같은 소스·의존성·실행 설명을 확인한다.

1. 직접 작성한 learner 경로와 제공 계산 경로 중 무엇을 옮길지 먼저 정한다.
2. P1–P4의 verify_export 시험을 사용할 때는 export_learner로 ../my_solver를 만든다.
3. 제공 계산은 make_calculation으로 별도 ../my_calculation에 만든다. 서로의 확인 도구를 혼용하지 않는다.

## 실행해서 무엇을 볼 것인가

첫 명령은 P1–P4의 learner 검사 경로다. 둘째 명령은 제공 계산을 별도로 옮긴다. 목적지는 모두 새 폴더여야 한다.

```bash
python tools/export_learner.py --output ../my_solver
```

```bash
python tools/make_calculation.py --output ../my_calculation
```

## 결과를 설명하기

제공 계산과 직접 작성한 learner는 서로 다른 출발점이다. 어느 쪽을 옮겼는지 명시해야 자신의 성취와 재현 범위가 드러난다.

**남길 증거.** 선택한 경로, 옮긴 소스 목록, 제공 함수와 직접 작성한 함수의 구분

**판단 기준.** 2점: 실제 소스 보존·의존성·실행 기록을 연결하고, 계산하지 않은 물리 결과까지 검증했다고 말하지 않는다. 최초 예측의 정오보다, 결과를 본 뒤 이유를 고치고 다른 입력에도 적용하는지를 본다.

## 막혔을 때

**힌트 1.** 먼저 출발한 폴더가 learner인지 calculation인지 확인한다.

**힌트 2.** SOURCE_FILES.json과 CALCULATION.json은 같은 확인 도구의 입력이 아니다.
