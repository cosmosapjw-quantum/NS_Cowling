# A00 · 실행환경과 입력의 의미

**선행:** 없음　 **독립 작업:** 0.5–1시간 (계획치)

## 프로그램이 끝났다면, 우리는 무엇을 확인한 것일까?

아직 별을 계산하지 않았다. 입력한 실수·정수·문자열이 되돌아왔다는 사실로 확인할 수 있는 것 하나와 확인할 수 없는 것 하나를 먼저 적자.

먼저 한두 문장으로 답한 뒤 아래 설명을 읽자. 첫 예측이 틀렸거나 아직 모르겠다고 적는 것은 감점하지 않는다.

## 필요한 관계와 읽을 위치

이 과제의 probe는 무차원이다. $\mathrm{workspace}=\mathrm{learner}$는 실행 경로의 이름이며 물리 정확도에 대한 진술이 아니다.

- `START_HERE.md`
- `support/fpm.toml`
- `learner/fpm.toml`

## 계산으로 옮기기

계산용 패키지에서 시작해도 된다. 아래 learner 선택은 입력 전달을 확인하는 시험이며 아직 별의 물리를 요구하지 않는다.

1. 새 디렉터리에서 입력 파일과 실제 실행할 소스를 확인한다.
2. run_assignment의 --plan으로 시험 경로를 읽고, --run으로 environment case를 실행한다.
3. 입력의 실수·정수·문자열을 바꾸고 실제 전달된 값과 반환 상태를 비교한다.

\newpage

## 실행해서 무엇을 볼 것인가

패키지 루트에서 실행한다. `--plan`은 경로만 확인하며 계산 성공을 뜻하지 않는다.

```bash
python tools/run_assignment.py A00 --plan
python tools/run_assignment.py A00 --run \
  --workspace learner --output ../A00_result.json
```

## 결과를 설명하기

입력 전달과 실행 대상을 구별했다면 충분하다. 이 시험에서 질량이나 모드의 정확성을 근거로 들었다면, 아직 계산하지 않은 양을 찾아 설명에서 빼자.

**남길 증거.** 도구 판본과 첫 명령 출력; 빌드 성공이 아직 증명하지 않은 것 두 가지

**판단 기준.** 2점 예: manifest→source→binary→input의 연결과, 이것이 방정식 검증을 대신하지 않는 이유를 함께 설명한다. 최초 예측의 정오보다, 결과를 본 뒤 이유를 고치고 다른 입력에도 적용하는지를 본다.

## 막혔을 때

**힌트 1.** 최초 실패 지점이 Python import, manifest 읽기, compiler, Fortran 상태 중 어디인지 찾는다.

**힌트 2.** 상수·별 계산을 호출하기 전에 environment의 입력 문자열과 workspace부터 확인한다.
