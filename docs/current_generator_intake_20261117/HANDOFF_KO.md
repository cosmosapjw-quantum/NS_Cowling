# Current-generator matching intake: implementation handoff

## Scope

`scripts/match_core_crust.py --current-generator-manifest PATH` creates a new, non-executing manifest with an exclusive file create. The no-argument legacy route remains the 8 crust × 5 core × 2 native method census (80 cells). The new intake enumerates 13 crust × 5 core × 6 method cells. The reviewed result is **390 requested, 1 eligible, 1 attempted, 1 admitted**. Here `requested` means coverage requested, not permission to run. Manifest creation does not call the generator or matcher.

`scripts/match_core_crust.py --current-generator-execute MANIFEST_PATH OUTPUT_ROOT` is the explicit intake execution mode. It requires the exact live sealed intake, exactly one eligible unattempted CSS cell, and an absent output root. It rechecks both source seals and uses the manifest's CompOSE paths. It sets `n_bridge=40` for one `run_pipeline` call and restores the legacy default afterward. It records the immutable input manifest SHA, current executable SHA, stage flags (`execution_started`, `source_verified`, `pipeline_invoked`, `matching_kernel_invoked`), raw result or exception, and outcome in `MATCH_EXECUTION.json`. The `attempted` flag becomes true only immediately before native `match-core` or `maxwell-transition` invocation. Executable lookup, source read, and source-support failures leave it false even if `run_pipeline` was entered; native failure and later failures preserve true. If `run_pipeline` raises without a returned invocation marker, attempted stays false. It also emits `MATCH_RESULT_CENSUS.json` with all 390 cells: the selected cell alone is attempted if the matching kernel was invoked; its `admitted` value reflects a surviving pipeline result with `admission.status=ADMITTED`, and the other 389 remain unattempted and unadmitted. A failure receipt and census remain on disk. This mode ran once at `data/current_generator_intake_20261117/runtime/run_001`; independent post-execution review returned `PASS_SCOPED` for that cell.

The one-run allowance is repository scoped. `data/current_generator_intake_20261117/ALLOWANCE_UNUSED.json` is the tracked template; the first execution atomically creates `data/current_generator_intake_20261117/runtime/CLAIM.json` with the manifest SHA, cell, output path, and current executable SHA before entering `run_pipeline`. A later call with another output path is refused without invoking the pipeline. Tests replace the allowance root with temporary state. The real claim now exists and the single allowance is consumed; another matching call is not authorized.

The current source pair is `SPG_M1` crust at `data/research_matching_20261117/spg/native_129_repaired/SPG_M1/generated` and `GM_GM1` core at `data/research_matching_20261117/integration/real_pairs_v2/core/GM_GM1/generated`. ## Seal distinction and dependency classification

SPG_M1 has an outer `RECEIPT.json` and native `RESULT.json`; GM_GM1 has an outer `DISPATCH.json` and native `RESULT.json`. The validator checks each exact outer receipt byte hash, the request hash, every outer-sealed artifact (including diagnostics when sealed), required CompOSE files, native identity/readback, and `SUPPORT.json`. Optional diagnostics are not promoted to physical acceptance gates. The support file still says cross-phase and cross-segment interpolation are `UNAPPROVED`; no bypass is implemented.

The historical GM_GM1 dispatch pins five generator source dependency hashes that differ from the current checkout. `data/current_generator_intake_20261117/DEPENDENCY_DIFF.json` records expected and observed hashes. The Astra scoped decision classifies this as `HISTORICAL_GENERATOR_DEPENDENCY_VERSION_DIFFERENCE`: sealed EOS/request/SUPPORT/receipt intake may proceed, but this is not generator reproduction or a dependency PASS. Any mismatch of an applicable sealed input yields `BYTE_IDENTITY_MISMATCH` HOLD.
