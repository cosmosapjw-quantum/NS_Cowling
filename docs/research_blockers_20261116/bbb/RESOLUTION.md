# BBB published-energy reconstruction: representation and source-domain resolution

Baseline: a49aaf9f82ddfda484e0f965aefdfe73aa7918f2. Worktree:
`/tmp/ns_blockers_a49aaf9_20261116`. Selected work: R2–R9, with native
C2–C8 calculations. No production core, shared build, stellar solver or existing
Python physics module was changed.

## Result and corrected completion criterion

The existing BBB_BHF2 generator is a complete implementation of its **declared
published-energy/PCHIP representation**, subject to the scientific limitations
below. Recomputing the microscopic BHF reaction matrix is **not a prerequisite**
for this particular claim. It would be a different calculation with a different
completion criterion. This closes an inflated microscopic-solver gate, not the
unresolved identity of the author's smooth EOS or Table 3 pressure prescription.

Three claims must remain separate:

| Claim | Evidence status | Exact completion meaning |
| --- | --- | --- |
| Reconstruct the published Paris+Urbana SNM/PNM energies and solve cold npemu composition with declared interpolation | implementation-verified and numerically checked | Table 1 source identity, all 16 energy nodes, native parity, charge neutrality and total first law tested |
| Reproduce the author's underlying smooth fit and every original Table 3 pressure | unresolved | Need the exact smooth SNM/PNM energy functions or coefficients plus the author's pressure derivative convention; a full BHF rerun is not logically necessary if these smaller inputs become available |
| Recompute the original microscopic Paris+Urbana BHF kernel | not attempted; separate scope | Requires a specified and validated Bethe–Goldstone/self-consistency implementation; no such claim follows from the source tables |

This does not silently redefine an explicit request for a microscopic calculation.
It resolves the scope of the existing composition-aware EOS generator. A final
barotropic Table 3 interpolator would be another valid, separately named data
product, but would not constitute a fresh composition calculation.

## Primary-source retrieval and what it supplies

The complete original arXiv v1 TeX archive was downloaded, hashed and inspected.
It contains one paper, seven plot PostScript files and the journal class, with no
separate coefficient table or code supplement. Direct parsing of the original
Table 1 and Table 3 exactly matches the existing locked JSON:
`b0d646a7b334d824d52af4c8bdd255f937f348f390c41e7ec2ba76736982234c`.
The URL/hash manifest and extracted numeric tables are in the sibling data directory.
Full external texts and RNS source/data reside only in the ignored execution cache
`build/blocker_bbb_sources`; `SOURCE_RELOCATION.json` preserves historical paths and
byte identity without altering the original execution receipt.

- [Baldo, Bombaci & Burgio, A&A 328, 274–282 (1997)](https://arxiv.org/abs/astro-ph/9707277):
  Table 1 gives the two nuclear-energy sequences; Eqs. (16)–(22) specify the
  parabolic approximation, np mass-difference omission, neutrality and beta
  equilibrium. The TBF strengths are A' = −0.0329 and U' = 0.00361, shared by
  Paris and AV14, in §2.1.
- The numerical-stability statement in §2.1 is approximately n ≤ 0.8 fm⁻³.
  Higher source rows already use the authors' numerical extrapolation.
  This is an approximate source-calculation boundary, not an independently
  established limit of the physical EOS.
- Eq. (29) supplies e(n)=Q^sigma(n)/(1+b n^sigma), with degree sigma = 3 or 4
  and b = 10⁻² to 10⁻³ explored. The actual coefficients and selected b used for
  the printed table are not given in the original TeX. It is not a fully
  specified analytic EOS that can simply replace PCHIP.
- [RNS EOS repository](https://github.com/rns-alberta/eos), pinned at
  `7ef71a578d2e52dede24bce055839f2b74f43721`, supplies a final `eosBBB2`
  barotrope, not nuclear energies or a BHF solver. Its 15 high-density pressures
  reproduce Table 3 exactly at displayed precision, while its number-density
  column is shifted (e.g. 0.159042 instead of 0.16 and 0.802354 instead of 0.8).
  Thus it cannot improve the Table 1 input precision.
  The accompanying `HnG.c` reconstructs baryon density from enthalpy and
  (rho+P/c²), using a 1.66e−24 g baryon normalization. This is a plausible
  explanation of the shifted column; this run has not established that the
  checked BBB2 file was generated by that exact revision of HnG.
- Public Exa and Parallel searches located the original article, institutional
  record, RNS delivery, and later BHF papers/presentations. No exact original
  Paris+Urbana author solver or missing fitted coefficient set was recovered.
  This is a bounded retrieval result, not a claim that no public implementation
  exists. No author was contacted.

The 1996 nucl-th/9607013 letter and its BHF2/BHF3 nomenclature are not substituted
for the 1997 Paris+Urbana BBB2 target.

## Computational contract and pressure

Let n be total baryon density in fm⁻³, y=n_p/n, delta=1−2y, and let e_0 and e_1
be the interpolated symmetric and neutron energies per baryon, in MeV, excluding
the common nucleon rest energy. With S=e_1−e_0,

\[
e(n,y)=e_0(n)+S(n)(1-2y)^2,\qquad
\mu_e=4S(n)(1-2y).
\]

Use cold, ideal relativistic electrons and muons, neutrino-free beta equilibrium,
charge neutrality n y=n_e+n_mu, common m_N c²=939 MeV, and
hbar c=197.3269804 MeV fm. Then

\[
\varepsilon=n[m_Nc^2+e(n,y)]+\varepsilon_e+\varepsilon_\mu,\qquad
P=n^2\left.\partial_n e\right|_y+P_e+P_\mu .
\]

The derivative is at fixed composition. Differentiating the *total* equilibrium
energy gives the same pressure, because the composition terms cancel through
neutrality and e_y=−mu_e. Differentiating just the baryon equilibrium trajectory
instead gives

\[
P_{\mathrm{baryon\ path}}
 =P-n^2\mu_e\,\frac{dy}{dn},
\quad
\frac{dy}{dn}=
\frac{4\chi S'(1-2y)-y}{n+8S\chi},
\quad
\chi=\sum_{\ell=e,\mu}\frac{\mu_e\sqrt{\mu_e^2-m_\ell^2c^4}}
 {\pi^2(\hbar c)^3},
\]

where a lepton contributes only above its rest-energy threshold.
Units are P,epsilon in MeV fm⁻³; chi in fm⁻³ MeV⁻¹; dy/dn in fm³.
The common mass convention leaves the beta composition unchanged.

Eq. (23)'s wording and the existing numerical composition-path diagnostic support
a specific interpretation of the original pressure discrepancy, but do not
identify the unavailable author implementation. We preserve the thermodynamic
pressure in production. The native reconstruction's Table 3 pressure discrepancy
is still as large as 65.1754%, while its proton-fraction discrepancy is only
0.000977944. No original-pressure agreement or full original-EOS equivalence is
claimed. Previous independent CubicSpline/path-pressure evidence remains in
`docs/research_generator_20261116/reference_cores.md`; it was not rerun here.

## New finding: extrapolated nodes enter below the nominal cutoff

PCHIP energy and first derivatives on a cell [n_i,n_(i+1)] depend on both endpoint
slopes, hence generally on nodes n_(i−1)..n_(i+2). In the current 16-row
representation, the cell 0.7<n<0.8 therefore uses the extrapolated 0.9 row.
At n=0.8 the energy is exactly the published local node, but its derivative uses
0.9. A metadata label based only on the queried n would miss this distinction.

The added native `source_state` evaluator provides an executable source-only
alternative: use the first nine rows and recompute the endpoint slope at 0.8;
reject n outside [0.08,0.8]. This alternative shares the parabolic/lepton model,
but is explicitly a different interpolation near its upper edge.

| n (fm⁻³) | Full-source P (MeV fm⁻³) | Source-only P (MeV fm⁻³) | Relative change |
| --- | ---: | ---: | ---: |
| 0.700 | 173.2603363831 | 173.2603363831 | 0 |
| 0.725 | 191.7536282737 | 191.1493638102 | −0.315125% |
| 0.750 | 210.4405380403 | 209.9439706264 | −0.235966% |
| 0.790 | 240.4278039836 | 241.8389574075 | +0.586934% |
| 0.800 | 247.8876613209 | 250.1520049393 | +0.913456% |

For n≤0.7 the two evaluations have identical energy, pressure and composition at
all tested points. At the 0.7 knot, a *right-hand second derivative* can already
depend on the next cell; PCHIP is C1, not C2. Sound-speed provenance therefore
also needs a side/cell convention at knots. The source-only alternative is a
concrete treatment of the source boundary, not a new microscopic calculation.

Production is unchanged. Retaining the full [0.08,1.5] representation is justified
when labelled published-energy reconstruction; use the provided nine-row
alternative when avoiding extrapolated *input rows* is required.
Neither option independently validates the nuclear model or supplies a complete
physical error budget.

## Native checks and finite source sensitivity

The new Fortran diagnostic evaluates 35 densities: all 16 nodes, 15 midpoints,
and four extra points in the affected 0.7–0.8 cell. Python only parses original
tokens, writes input, invokes compilation/run, and summarizes emitted values.
All scientific evaluation and beta solves are Fortran. It uses at most one
compute process with BLAS/OpenMP thread limits of one.

| Check | Observed result |
| --- | ---: |
| Original TeX Table 1 and Table 3 versus locked JSON | Exact numeric identity |
| PCHIP energy error at source knots | 0 MeV |
| Max independent-evaluator/production epsilon difference | 6.82e−13 MeV fm⁻³ |
| Max independent-evaluator/production P difference | 1.14e−13 MeV fm⁻³ |
| Max independent-evaluator/production Yp difference | 1.67e−16 |
| Max charge residual | 3.89e−16 fm⁻³ |
| Total-first-law central-difference check at 19 non-knot points | 3.96e−8 scaled residual |
| Same check with step halved | 9.96e−9; expected second-order decrease |
| Truncated evaluator rejection at 0.079999 and 0.800001 | Passed |
| Truncated/full equality at tested n≤0.7 | Passed |
| PCHIP versus independent local four-node cubic P spread | Up to 4.40098% on this sample |

The first-law scale is max(1 MeV fm⁻³,abs(P)); it is not an accuracy estimate of
the true nuclear EOS. The new PCHIP evaluator independently solves beta equilibrium
but deliberately uses the same stated interpolation algorithm and production
free-fermion primitive. This is an implementation/formula cross-check, not a fully
independent microscopic model. Local Lagrange interpolation is a separate
representation control, not an improvement adopted into production.

Original printed tokens determine half a final displayed digit, including
0.5 MeV for `17.` and `537.`. All vertices of each active local PCHIP precision
box were actually evaluated: 64 or 256 cases per sampled density, with the beta
composition resolved for every case. Selected finite pressure envelopes are:

| n (fm⁻³) | Nominal P | Corner min P | Corner max P |
| --- | ---: | ---: | ---: |
| 0.08 | 0.385892 | 0.271671 | 0.499985 |
| 0.16 | 2.505193 | 2.436537 | 2.540233 |
| 0.80 | 247.887661 | 247.711224 | 248.063562 |
| 1.50 | 1190.165635 | 1183.080669 | 1197.247355 |

These are **finite corner-sample envelopes**, not rigorous extrema of the
nonlinear map, confidence intervals, or nuclear-theory uncertainties. The
half-last-digit convention itself assumes rounding rather than undocumented
truncation. The low-density spread and source-support choice belong in the
representation error budget. The large Table 3 mismatch persists in these
specific perturbations; we do not infer a universal impossibility from them.

A finite table alone cannot define a unique between-node derivative. For example,
on one cell let t=(n−n_i)/(n_(i+1)−n_i) and add
a*t²(1−t)² to e_0 inside that cell and zero outside. This C1 perturbation preserves
every sampled energy and endpoint slope, while changing pressure inside the
cell. Its free amplitude demonstrates why interpolation spread cannot become a
certified source error bar without extra smoothness or model information.

## Reproduction and retained artifacts

From the repository root:

~~~sh
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  python3 fortran_eos/tests/bbb_source_runner.py
~~~

The driver compiles only `compose_eos_types.f90`,
`compose_eos_core_native.f90` and the new diagnostic into the separate
`/tmp/ns_bbb_source_native_20261116` directory. It does not modify the shared
production build. The run takes about one second on the current device. Missing external source
files are fetched into the ignored cache and checked against retained SHA256s;
`--source-cache` selects another local cache. The repository does not publish the
full paper or full RNS code/data.

- `fortran_eos/tests/bbb_source_diagnostics.f90`: native source evaluator,
  bounded source alternative, controls and assertions.
- `fortran_eos/tests/bbb_source_runner.py`: source-token parsing and run frontend.
- `data/research_blockers_20261116/bbb/result.json`: measured results,
  execution command, dependencies and executable hash.
- `native_source_diagnostics.csv`: all full/truncated/control/corner results.
- `microscopic_source_only_native.csv`: sorted evaluated nine-row source-only
  states, for diagnostic reuse; not a full-grid production CompOSE table.
- `SOURCE_MANIFEST.json`, `compile.log`, `native_run.log`:
  source URLs/hashes, pinned RNS provenance and actual execution evidence.
  `SOURCE_RELOCATION.json` records the move of full external files into the ignored
  cache. No explicit RNS redistribution license was established by the repository
  metadata/root-file check, so the complete RNS code/data are not republished.

Positive next action is to keep BBB usable under its explicit representation
contract and attach source-cell provenance. Exact author-fit recovery remains a
small, precise source-identity task: the two smooth nuclear-energy representations
and selected extrapolation parameters, with the pressure derivative convention.
It should not halt the existing thermodynamic published-energy generator or turn
into a blanket requirement to implement an entire new BHF solver.
