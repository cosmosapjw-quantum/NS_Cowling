\subsection{계산으로
옮기기}\label{uxacc4uxc0b0uxc73cuxb85c-uxc62euxae30uxae30}

P1--P4의 자동 검사는 직접 구현한 learner의 독립 export 경로다. 제공
계산만 사용하는 독자는 별도 계산 폴더에서 같은 소스·의존성·실행 설명을
확인한다.

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  직접 작성한 learner 경로와 제공 계산 경로 중 무엇을 옮길지 먼저
  정한다.
\item
  P1--P4의 verify\_export 시험을 사용할 때는 export\_learner로
  ../my\_solver를 만든다.
\item
  제공 계산은 make\_calculation으로 별도 ../my\_calculation에 만든다.
  서로의 확인 도구를 혼용하지 않는다.
\end{enumerate}

\end{verbatim}

\begin{verbatim}
python tools/make_calculation.py --output ../my_calculation
\end{verbatim}

\subsection{결과를
설명하기}\label{uxacb0uxacfcuxb97c-uxc124uxba85uxd558uxae30}

제공 계산과 직접 작성한 learner는 서로 다른 출발점이다. 어느 쪽을
옮겼는지 명시해야 자신의 성취와 재현 범위가 드러난다.

\textbf{남길 증거.} 선택한 경로, 옮긴 소스 목록, 제공 함수와 직접 작성한
함수의 구분

\textbf{판단 기준.} 2점: 실제 소스 보존·의존성·실행 기록을 연결하고,
계산하지 않은 물리 결과까지 검증했다고 말하지 않는다. 최초 예측의
정오보다, 결과를 본 뒤 이유를 고치고 다른 입력에도 적용하는지를 본다.

\subsection{막혔을 때}\label{uxb9c9uxd614uxc744-uxb54c}

\textbf{힌트 1.} 먼저 출발한 폴더가 learner인지 calculation인지
확인한다.

\textbf{힌트 2.} SOURCE\_FILES.json과 CALCULATION.json은 같은 확인
도구의 입력이 아니다.

\subsection{다음 만남에 다시
묻기}\label{uxb2e4uxc74c-uxb9ccuxb0a8uxc5d0-uxb2e4uxc2dc-uxbb3buxae30}

다음 회차에는 원래 폴더 경로를 보지 않고 필요한 소스·입력·공용 함수가
어디 있는지 설명한다. 먼저 짧게 답한 뒤 본문과 자신의 기록을 열어
확인한다.

\textbf{범위.} 소스 보존과 build 성공은 별 전체의 물리 검증과 다르다.
작성하지 않은 함수는 새 폴더에서도 미완성이다.
