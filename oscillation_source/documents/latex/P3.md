**선행:** P2　 **독립 작업:** 0.5–1시간 (계획치)

## 빌드가 끝나면 물리 검증도 끝나는가?

새 위치에서 environment case가 성공했다. EOS·TOV·고유값 중 어느 단계까지 검증되었다고 말할 수 있는지 먼저 적자.

먼저 한두 문장으로 답한 뒤 아래 설명을 읽자. 첫 예측이 틀렸거나 아직 모르겠다고 적는 것은 감점하지 않는다.

## 필요한 관계와 읽을 위치

이 과제는 물리 방정식의 추가가 아니다. 동일한 소스와 공용 의존성을 보존하고, 다른 위치에서 실제로 빌드·실행할 수 있는지 확인한다.

`notes/chapters/ch11.md`, `tools/export_learner.py`, `tools/verify_export.py`, `tools/make_calculation.py`

## 계산으로 옮기기

P1–P4의 자동 검사는 직접 구현한 learner의 독립 export 경로다. 제공 계산만 사용하는 독자는 별도 계산 폴더에서 같은 소스·의존성·실행 설명을 확인한다.

1. 검사 도구의 --build로 별도 사본에서 소스를 빌드하고 작은 입력을 실행한다.
2. 아래 명령은 SOURCE_FILES.json을 가진 learner export에 사용한다. CALCULATION.json만 있는 폴더에는 적용하지 않는다.
3. 빌드 성공과 environment 실행이 확인한 범위를 적는다.

## 실행해서 무엇을 볼 것인가

P0의 `export_learner.py`로 만든 `../my_solver`에 사용한다. 출력 파일은 새 이름으로 둔다.

```bash
python tools/verify_export.py --export ../my_solver --build --output ../build_check.json
```

## 결과를 설명하기

이 과제는 빌드와 입력 전달을 확인한다. 물리 결과는 해당 입력의 과학 시험이 필요하다. 시작 단계 A00에서 했던 구분을 여기서 다시 적용한다.

**남길 증거.** 소스 빌드와 작은 입력의 명령·결과, 아직 검증하지 않은 물리량

**판단 기준.** 2점: 실제 소스 보존·의존성·실행 기록을 연결하고, 계산하지 않은 물리 결과까지 검증했다고 말하지 않는다. 최초 예측의 정오보다, 결과를 본 뒤 이유를 고치고 다른 입력에도 적용하는지를 본다.

## 막혔을 때

**힌트 1.** 경로는 실행한 현재 폴더가 아니라 fpm.toml의 위치를 기준으로 해석한다.

**힌트 2.** SOURCE_FILES.json에 기록된 파일과 실제 learner 파일의 내용을 비교한다.
